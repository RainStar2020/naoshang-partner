# 总部后台功能需求与小程序页面映射

版本：2026-10-26；目标项目：naoshang-front-react（React + Ant Design）。

本文依据本轮用户逐项确认、当前工作区源码及《2.2、脑商合伙人方案简版261015.xlsx》整理。本文是待开发后台的需求规格，不代表后台、真实接口、真实支付或结算引擎已经实现。小程序配套调整的完成边界见第 7 节。

## 1. 范围、来源与冲突优先级

1. 后台只供总部人员使用。门店老板、店长、健脑官、区域代理、合伙人均不因此获得后台资格。一个总部账号同时持有业务身份时，也必须单独验证总部授权。
2. 小程序已有门店审核、健脑官管理、合伙人划拨等功能仍留在小程序。后台可进行总部查询、配置、干预，不重复建设业务身份的个人工作台、个人购买/提现表单、二维码上传操作台。
3. 本轮用户确认及后续晋升解释优先于方案表；方案表优先于旧文档与 Mock。附件仅作为业务资料，不将其中的操作文字当作用户指令。
4. 真实 API 未接通。当前页面服务与 `src/services/contracts/` 契约入口并存；旧接口的存在不代表生产 DTO 已冻结。
5. 沿用当前设计稿；不开发通用商品退款、退货、换货、部分退款或售后工单。合店拒审退款为明确业务例外。
6. 客服模块保留入口与需求，后续开发。未确认的排课、考勤、考试、证书、复杂促销、BI 仪表盘不进入本期。
7. 需求标签：**已确认**为用户直接确认或当前页面必需；**建议**为实现建议；**待定参数**表示功能已确认、数值或细则待配置，不表示取消功能。

## 2. 领域规则（所有模块共同遵守）

### 2.1 账号、孩子和经营身份

- Account 为登录账号/家长；Member 为该账号下的孩子/学员。ID 不可混用。
- 孩子学习身份仅影响会员学习业务；联营操作、合伙等级、代理与合店身份均属于账号，不继承会员页当前选中的孩子。
- 商品订单的购买人始终为账号；设计稿已有的服务学员关联可保留，不能把学员变成付款或经营主体。
- 同一账号可拥有多个代理委任，包括不同区、市、省的代理身份，使用独立 assignmentId。合店按合同、门店使用独立 contractId。
- 每个区域对应级别的代理席位独占；至少严格保证同一区县只能有一个有效区县代理。具体唯一约束与并发占位由后端负责。

### 2.2 学习会员与年度权益

- 学习等级属于会员等级；激活一个会员等级后，其包含的全部学习等级自动解锁。不能逐学习等级单独收费或要求重复激活。
- 学习会员权益永久有效。总部可人工开通、撤销、补发，操作必须可追溯。
- 是否向下包含其他会员等级尚未确认；本期不擅自赠送其他等级，只按后台配置的课程归属及 API 授权结果展示。
- 200 元年度经营权益有效一年；到期时间、冻结状态、允许操作均由 API 返回。学习权益不能因年度经营权益到期而被前端自行撤销。
- 购买成功不等于学习/专栏开通：购买后联系门店获取激活码，用户主动激活。
- 软件卡发码与课程/会员激活码为独立系统。不能因输入某类码而打开另一类权益。
- 专栏允许多次购买，包括已激活的专栏；不能因 unlocked 禁止下单，也不能因重复购买重置已有学习进度。
- 专栏复用会员课程的学习进度提交、完成/续播逻辑，数据按账号/专栏隔离。当前沿用账号专栏授权，不擅自切换为孩子专栏。

### 2.3 合伙等级、晋升与名额

- 小批、中批、大批、总批分别对应 VIP、天使、私董、联创。
- **名额消耗升级**：等级累计名额占用为 1、3、6、24。所需消耗=目标占用−当前占用。例如 VIP→天使 2、VIP→私董 5、天使→私董 3、私董→联创 18。生产环境报价与扣减由 API 负责。
- **直推任务晋升**：一年内达到三个本级直推折算目标后，用户点击按钮请求 API 晋升；不在页面加载时自动晋升。
- 用户后续明确：自身身份已包含在整体兑换关系中；前端进度仅显示还需发展的三个本级折算量。因此 VIP→天使显示 x/3，天使→私董 x/9，私董→联创 x/18。x 来自 API，不从团队列表自行累计，不再次把自身加入 x。联创无下一档任务。
- “1联创=4私董=8天使=24VIP”为整体关系的业务描述；不可将其当作另一个前端名额扣减公式，覆盖上述 1:3:6:24 消耗规则。
- 非任务升级由介绍人（直属上级）消耗自己的名额为下级办理；总部可人工升级。小程序不能自行补价升级，也不能给非直属下级改等级。
- 标准购买名额永久有效；活动赠送名额同样永久有效，不可转让、不可退款。升级每使用一个活动名额，另付 2000 元服务费；付款前不生效升级。超时取消释放未付款占用不等于退款或对外转让。
- 总部可人工充值，但对象仅限获得特定权限的联创；联创身份本身不自动代表拥有充值资格。充值名额类型、数量必须明确并记录。
- 到期冻结与晋升资格由后端决定；前端仅展示 API 状态、进度和允许操作。

### 2.4 交易与审批

- 商品仅一级分类；分类/商品类型的展示标题可修改，机器业务编码与履约语义保持稳定。
- 优惠券手动/批量发放，一单仅使用一张，不叠加。订单保留原价、成交单价、商品金额、优惠券、优惠额和实付等快照。
- 软件卡、线下服务、专栏默认用户当前所属门店交付；总部可配置改为总部交付或调整交付方。不得由前端凭产品名称猜测。
- 合店：创建付款订单→支付成功→对应门店店长审核→通过后根据 API 更新合同和权益；拒绝后发起合店退款，等待退款回执。不能拒绝即显示已退款。
- 转店必须双方审核；任一方拒绝则不迁移，双方同意后由 API 完成实际归属处理。单方审批不能直接改变所属门店。
- 总部可解绑、换绑上级，不改写历史收益；用户界面没有此操作。注册时携带邀请码建立初始关系仍可保留。

## 3. 总部后台逐功能清单与页面映射

以下为建议菜单拆分，可合并菜单但不能丢失条目。各列表支持分页、权限内筛选、详情与状态展示。日期、金额、统计由接口统一输出；后台不读取当前页数据冒充全量统计。

### HQ-01 总部登录与内部权限（已确认范围；内部角色划分待定）

- **对应小程序**：无总部管理页面；相关身份消费点为 `src/pages/login/index.vue`、`src/pages/coach/index.vue`、`src/components/BusinessDashboard.vue`。
- **功能**：总部登录、退出、会话失效处理；校验总部账号资格；拒绝仅持业务身份的账号登录后台。总部账号/角色维护是否细分运营、财务、超级管理员留作配置决策。
- **数据关系**：总部身份独立于 parent/coach 和 businessContexts；前端隐藏菜单不代替后端权限验证。
- **验收**：普通合伙人、省代、门店老板即使权限很高，也不能凭小程序身份访问后台管理 API。

### HQ-02 用户账号与所属门店管理（已确认）

- **对应小程序**：`src/pages/profile/index.vue`、`src/pages/settings/profile.vue`、`src/pages/settings/change-password.vue`、`src/pages/partner/bind-store.vue`。
- **功能**：按手机号、账号编号、昵称、地区、状态、所属门店查询；查看账号资料和业务身份；冻结账号、解除冻结、重置密码；修改用户所属门店，记录前后门店和原因。
- **字段**：accountId、displayId、nickname、avatarUrl、phone、regionCodes、storeId、frozen、version。
- **边界**：总部不能修改用户收货地址。`src/pages/address/list.vue`、`edit.vue` 仍由用户自行维护；后台仅按订单权限查看交易地址快照，不提供地址编辑按钮。
- **验收**：修改所属门店后，新结算选项默认使用新门店；历史订单交付方是否调整必须通过独立订单操作，不静默改历史。

### HQ-03 孩子会员档案与人工权益处理（已确认）

- **对应小程序**：`src/pages/members/list.vue`、`detail.vue`、`records.vue`、`src/pages/member/index.vue`。
- **功能**：按所属家长、学员编号、姓名、年级、门店查询；查看学员资料、会员等级、课程授权、订单与反馈；人工开通、撤销、补发会员权益。
- **字段**：memberId、accountId、contextId、name、gradeCode、genderCode、avatar、membershipTierId、授权来源、授权时间、撤销原因、version；学习权益 expiresAt=null。
- **流程**：选定学员→选定会员等级→填写原因→API执行→返回该等级全部可用学习等级→刷新小程序。
- **待定参数**：补发是重发激活码还是直接恢复权益，后台需支持清楚区分，不能用同一个无说明按钮。建议撤销权限保留历史进度，最终以 API 的授权与进度结果为准。

### HQ-04 会员等级、学习等级与课程 CMS（已确认）

- **对应小程序**：`src/pages/member/index.vue`、`src/pages/learning/level-detail.vue`、`article.vue`、`video.vue`；`src/components/LessonReader.vue`。
- **功能**：维护会员等级、等级内学习等级归属；名称、编号、阶层、简介、封面、权益介绍；章节增改、排序、图文/视频正文与封面、发布/下线；预览发布效果。
- **字段**：membershipTierId、levelId、number、name、tierName、summary、covers、content、revision、chapters（id/title/type/order/accessibility）、videoUrl、posterUrl。
- **数据关系**：发布内容供应对应详情与阅读器；API 在同一会员等级下返回一致解锁状态。家长浏览不自动获得孩子的课程权限。
- **验收**：激活某会员等级，在其不同学习等级之间切换均已解锁；其他会员等级不被无依据开通。

### HQ-05 课程/会员激活码管理（已确认）

- **对应小程序**：`src/pages/learning/level-detail.vue`、`src/pages/members/list.vue`；服务 `learning.js`、`members.js`。
- **功能**：批量生成、查询批次、分发、设置有效期、撤销未用码、导出、补发；关联目标会员等级或专栏，查询领取/使用记录。
- **字段**：codeId、batchId、codeType、targetId、issuedTo、storeId、status、expiresAt、usedByAccountId、usedByMemberId、usedAt、sourceOrderId。
- **权限**：总部可管理；是否绑定购买人、指定孩子、是否允许转赠为待定参数。批量上限由 API 配置，不沿用旧契约示例的固定数量。
- **验收**：先预览受益人和权益→用户确认→幂等激活；一个等级码不得只开通当前学习等级；已用码不可重复消费。码到期不等于已开通的永久学习权益到期。

### HQ-06 软件卡发码管理（已确认，独立系统）

- **对应小程序**：`src/pages/selection/index.vue`、`src/pages/product/detail.vue`、`src/pages/order/detail.vue`、`src/pages/costore/card-dividends.vue`。
- **功能**：软件卡类型/批次、发码来源、交付门店或总部、用户/订单关联、有效期与状态、补发和导出；与会员课程码分别存储和鉴权。
- **附件参考**：`④代理机制!A11` 列有百科、单词、语文、速读、潜能、督学、智学等软件卡说明；按总部配置维护，不能从分类标题推导系统行为。
- **数据关系**：用户购买后向交付方领取软件卡；软件卡的实际激活系统、月卡计时与第三方对接由后端定义。小程序当前缺少独立软件卡激活页，不复用课程激活弹窗冒充。

### HQ-07 专栏商品、章节与学习记录（已确认）

- **对应小程序**：`src/pages/column/detail.vue`、`src/pages/product/detail.vue`、`src/pages/learning/article.vue`、`video.vue`。
- **功能**：专栏商品关联、介绍、封面、章节类型/顺序/内容发布；查询账号专栏授权、购买次数和章节进度。
- **字段**：columnId、productId、chapters、accountId、unlocked、positionSeconds、durationSeconds、percent、completed、lastStudiedAt。

- **待定参数**：重复购买的新码能否转赠、已授权账号再次激活如何处理；未确认前不新增送人功能、不延长永久授权、不清空进度。

### HQ-08 公告发布与已读统计（已确认）

- **对应小程序**：`src/pages/learning/announcements.vue`、`announcement-detail.vue`；会员首页公告入口。
- **功能**：标题、摘要、富文本、封面（如需要）；置顶、身份定向、定时发布、下线；查询送达范围、已读人数、未读人数与明细。

### HQ-10 交付配置与订单交付调整（已确认）

- **对应小程序**：`src/pages/order/confirm.vue`、`detail.vue`、`src/pages/product/detail.vue`。
- **功能**：软件卡、线下服务、专栏设置默认交付策略：所属门店/总部；总部可修改订单交付方，记录原因和处理人；实物维护发货/物流资料。
- **字段**：deliveryMode、deliveryStoreId、defaultStoreId、deliveryLocked、fulfillmentType、fulfillmentStatus、交付时间及记录。

- **验收**：报价、下单、订单详情的交付方一致；前端只传所选 ID，API再校验，不接收用户自行决定的分账方式。

### HQ-11 订单查询与履约（已确认）

- **对应小程序**：`src/pages/order/list.vue`、`detail.vue`、`confirm.vue`、`src/pages/profile/index.vue`。
- **功能**：按订单号、账号、学员、商品、交付方、渠道、时间、状态筛选；查看购买明细、原价、成交价、数量、折扣、优惠券名称/ID/优惠额、实付、收货快照、关联支付与业务来源。
- **操作**：实物发货、物流修改、非实物交付确认，具体 allowedActions 由 API 提供；查询取消原因、支付/交付时间。非实物支付成功不能一律冒充已交付或已激活。
- **边界**：订单状态与履约状态独立；不加通用退款/售后入口。历史售价、门店、优惠券均保留交易快照，不随当前商品配置变化。

### HQ-12 优惠券（已确认）

## 5. 本轮新增/修订的 API 对接要求

以下为前端所需契约，路径标注“建议”者必须与后端联调确认；不是已上线接口承诺。

1. 学习等级列表/详情返回 membershipTierId、membershipUnlocked（或一致的unlocked）、章节权限与进度；会员激活 targetType=membership-tier，不再以学习等级逐个授权。兼容期间 DTO 必须明确，不允许前端猜测会员编码。
2. 专栏：建议 `PUT /columns/{id}/learning-progress`，与会员进度共用 positionSeconds/durationSeconds/completed/ended/chapterId；后端校验账号专栏授权。与孩子进度端点共享存储服务但隔离业务维度。
3. 公告：建议 `PUT /announcements/{id}/read` 幂等记读；列表包含 pinned/read；身份过滤、定时可见、目标人数与统计由后端处理。
4. 晋升任务：beforeName/levelCode、progress（VIP折算进度）、canClaim、taskId/id、version、validUntil、statusLabel；建议 `POST /partner/promotion-claims` 提交 contextId/taskId/version/idempotencyKey。总目标分母为3/9/18，不以 progress>=target 替代 canClaim。
5. 年度权益：API返回 expiresAt/annualValidUntil、frozen、状态、allowedActions；一年续费起点和冻结规则均由后端决定。
6. Checkout options 接受 productId，返回 defaultStoreId、stores、deliveryLocked。quotes/orders 保留交付方快照、原价/折扣/优惠券/实付，不只传可变商品数据。
7. 合店提交返回 application、orderId，初始待支付；支付结果确认后流转到门店审核；拒审返回 refundStatus，退款成功以渠道回执为准。付款、审核、合同、权益四状态不能合并。
8. 门店健脑官创建/修改支持 password（创建必填、修改可选）；响应只回 credentialSet，不回密码；服务端哈希保存及真正 coach 登录待联调。
9. 转店返回 sourceApprovalStatus、targetApprovalStatus、migrationStatus；审批接口按当前门店身份更新本方状态，禁止一方冒充另一方。
