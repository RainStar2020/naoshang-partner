# 验收与交接

## 1. 需要运行的实际命令

在仓库根目录，现有scripts可用：

```sh
npm run test:auth
npm run build:h5
npm run build:mp-weixin
```

涉及认证改动运行test:auth；涉及共享运行时、路由、组件或业务页面时检查目标H5与小程序构建。仅改文档无需构建应用。命令失败记录真实错误、是否原有问题及影响，不改动无关业务强行让结果变绿。当前没有声明存在lint/typecheck脚本，不能在交接里捏造已执行。

开发预览脚本dev:h5、dev:mp-weixin已存在。小程序构建成功不代表真机测试通过。微信授权、支付、订阅、相册权限等需要真实环境才能验收，不能以H5模拟代替。

## 2. 按风险验证

视觉小改动用构建/截图与实际交互核对，不写逐条镜像CSS的测试。领域规则适配、并发请求失效、幂等重试、订单状态映射等需要有意义用例；不能写测试只断言实现同一句代码。

公共基线：loading/ready/empty/error/forbidden、分页结束、重复提交、断网重试、会话过期、进入/返回/刷新、切身份旧请求、长文字、键盘、安全区、图片失败。关联设计截图覆盖用图号记录，不只写“已还原”。

高风险：同激活码重复只发一次权益；同名额划拨不重复扣；支付SDK返回不能直接入账；取消/支付并发一致；提现冻结/失败退回正确；跨孩子/店/区域越权被后端拒绝；私有附件不能通过猜id访问。前端单测只能验证调用和展示，原子事务/鉴权须后端联调证据，不夸大前端测试范围。

## 3. 任务记录

04 JSON是初始任务索引。建议在执行时将当前任务副本保存为docs/ai-frontend-v1/execution/<taskId>.json或项目既有任务位置，不整体覆盖其他任务进度。记录：taskId、scope、status、designRefs、changedFiles、contractStatus、assumptions、unresolvedQuestions、verification、nextStep。执行记录不要写入token、密码、真实支付参数或收款资料。

接口状态：proposed / mock-only / backend-confirmed / integrated。页面维度：ui、mockFlow、remoteIntegration、h5、mpWeixin。结果不确定写unverified，不用done模糊表达。阻塞要具体到动作和问题编号，可继续的部分继续实现；不能把整包所有任务永久卡在第一个接口问题。

## 4. 完成等级

- UI完成：布局与状态已实现，图片对照/交互已验证，真实业务仍可能未接入。
- Mock完成：使用隔离模拟数据走通正常及必要异常路径；注明示例业务规则。
- 已联调：真实接口、字段、权限、异常已验证，未必完成双端设备验证。
- 已验证：本次任务约定范围的代码、契约、关键路径和目标平台验收均有证据。

任务明确只要求文档、静态页或Mock时，按该范围完成即可，但不能同时宣称支付/短信/收益已上线。

## 5. 面向用户的交接格式

“完成了什么及对应图号；主要文件和入口；实际验证命令/设备及结果；哪些仍是Mock或未确认；具体剩余问题和可继续任务。”只保留影响判断的细节。不要以“所有页面开发完成”代替覆盖清单；不要向用户报告没有实际运行的测试。
