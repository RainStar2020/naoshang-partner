# 后台富文本内容约定

更新时间：2026-10-22。来源：用户本轮明确要求。该要求优先于旧设计图中的示例正文和上一版任务卡的填充建议。

## 已确认范围

- 素材模板、等级权益的内容暂时留空，后续由客户在管理后台上传文字、图片等内容。
- 前端保留栏目结构和渲染位置，不复制截图中的商品、人像、营销文案、权益描述，也不编写“示例权益”作为默认正文。
- 当前会员等级详情已经使用ManagedRichContent展示内容；Mock的content.nodes=[]、summary=''、covers=[]。无正文不显示“后台尚未配置”等实现提示，也不显示虚构图片占位块。
- 后续合伙等级权益/素材模板采用相同内容约定，客户端不内置其固定正文。本轮没有开发客户管理后台或素材库编辑器。
- 等级编号/标题是导航元数据；实际学习权限、费用、分配比例、有效期属于业务规则，由后端字段决定，不由富文本正文推断。

## 发布格式（前端提案，待后端确认）

统一正文字段content：

```json
{
  "version": 1,
  "format": "nodes",
  "nodes": []
}
```

发布后nodes可包含p/div/span/strong/em/u/s/br/h2/h3/ul/ol/li/blockquote/img及text节点。文字节点使用{type:'text',text:'客户文字'}；图片节点使用{name:'img',attrs:{src:'https://已授权的媒体地址',alt:'说明'}}。这只是格式说明，不作为应用默认数据。媒体域名与访问策略以后端配置为准。

normalizeContent在端上对白名单节点过滤，移除脚本、事件、链接和任意样式；图片只接受HTTPS。后端仍须做内容消毒、图片类型/归属/权限校验及必要审核，前端过滤不是上传安全检查的替代。私有权益图片不能发布永久公开地址，应返回鉴权/签名链接。

管理后台可采用其选定的富文本编辑器；若编辑器输出HTML/Delta，后端发布时转换为上述节点JSON。当前端不直接接收任意HTML。需要新增表格、链接、视频等能力时，先扩展版本/渲染器/平台验证，不静默丢弃有业务意义的新格式。

标题、摘要、封面列表、正文分别字段化；内容revision、publishedAt、publicationStatus建议由后端返回。尚未发布/撤稿不可当作已发布正文缓存。相同正文格式不表示素材模板、权益介绍、受保护课程正文共用授权范围。

## 当前接入与后续边界

- 等级详情GET /learning/levels/{levelId}保留content/summary/covers/chapters；现有实现以原始DTO接入，后端envelope确认后集中适配。
- 家长浏览导航元数据暂提案GET /learning/levels，返回{levels:[]}，不得返回某个孩子学习权益。孩子仍用GET /members/{memberId}/levels。
- /me/bootstrap.contexts的本轮最小字段：id/accountId/mode(parent|child)/memberId?/name/displayId/grade?/badge。其他区域/门店身份不在本轮学习选择器中显示。
- 素材详情未来GET /materials/{id}需补content字段，是否公开/可下载/可合成海报由独立allowedOperations决定，不能根据正文存在就开放编辑。
- Mock使用两名演示学员覆盖已解锁/未解锁；初始正文、封面、课程目录与公告均为空，避免伪造后台已上传的数据。
- Mock第二名学员可用DEMO-L1至DEMO-L10验证对应等级激活；码仅在当前浏览器运行期模拟、按账号隔离，刷新后重置，不是正式激活规则。
